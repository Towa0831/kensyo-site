# 前の状態に戻す（差し戻し）

このサイトでは、保存したすべての変更が履歴として残っている。これがバックアップになっている。本番に公開するたびに `release-日付-時刻` という目印（タグ）も付いている。

CLAUDE.md の「提案 → OK → 保存 の流れ」に沿って進める。**確認をもらうまで、ファイルは戻さない。**

## 1. 履歴を調べる（最初の返事）

```
git fetch --tags origin
git log --date=format-local:'%Y-%m-%d %H:%M' --pretty='%h %ad %s' -- content site.yml images templates assets
git tag -l 'release-*' --sort=-creatordate
```

- 履歴が途中で切れているように見えたら、`git fetch --unshallow --tags origin` を実行してから調べ直す
- 特定の記事の履歴は `-- content/news/ファイル名.md` のように指定して調べる
- 時刻は日本時間で表示される
- 戻す先の内容は `git show <番号>:content/news/ファイル名.md` で確認できる

## 2. 戻す先を確認する（最初の返事）

Issueの内容から戻す対象と時点を判断し、候補を表にして見せる。英数字の記号（コミットの番号など）は見せず、番号を振って選んでもらう。

| 番号 | 日時 | 内容 |
| --- | --- | --- |
| 1 | 10月7日 15:30 | 求人「一般事務スタッフ」の給与を変更 |
| 2 | 10月5日 10:12 | お知らせ「ホームページを公開しました」を追加 |

候補が1つに絞れるときは、**何がどう変わるか**（「給与が 月給25万円 から 月給22万円 に戻ります」など）を具体的に書き、
「この内容で戻してよければ `@claude 1番でOK` とコメントしてください」と案内する。

## 3. 戻す（OKが出たとき）

- **記事ひとつ**：`git restore --source=<戻す先> -- content/news/ファイル名.md`
- **サイト全体**：`git restore --source=<戻す先> -- content site.yml images templates assets`
  - 戻す先の時点より後に追加された記事は、ファイルを消さずに `status: 非公開` にする
- **非公開にした記事を復活**：`status` を「公開」に戻すだけでよい

戻したあとは `git diff --stat` で変更を確かめ、`python build.py --check` を実行してから保存する。返事は CLAUDE.md の「保存のしかた」に従う（確認用ページで確かめてから、Create PR で公開申請を作り、公開ボタンを押すと本番に反映される）。

## 急いで本番を戻したいとき

担当者が急いでいる場合は、Issueを待たずに次の方法でも戻せると伝える。

1. GitHubの「Pull requests」タブで、問題の内容を公開したときの公開申請（Closed の中にある）を開く
2. 一番下の「Revert」ボタンを押すと、取り消し用の公開申請ができる
3. その公開申請で「Squash and merge」→「Confirm squash and merge」を押すと、2〜3分で本番が元に戻る
