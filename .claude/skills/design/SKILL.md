# デザイン（CSS）の変更

見た目は `assets/css/style.css` の1つのファイルで決まっている。このファイルは **全体を書き換えてよい**。
CLAUDE.md の「提案 → OK → 保存 の流れ」に沿って進める。

## 変えてよい範囲

- `assets/css/style.css`：自由に変えてよい（色、文字、余白、配置、形、スマートフォン表示など）
- `templates/`：これまでどおり **文言だけ**。HTMLの骨組み（タグ、`class`）は変えない
- HTMLの骨組みを変えないとできない依頼（例:「メニューの並び順を変えたい」「新しい欄を足したい」「ページを増やしたい」）は、対応せず「管理者に相談してください」と伝える。CSSだけで実現できる場合（例: 見た目の並びを横から縦にする）は対応してよい

## 1. 聞き取り

次のことが分からなければ質問する（一度に3つまで）。

- どこを変えたいか（サイト全体、トップの上部、お知らせ一覧、ボタン、スマートフォンでの表示など）
- どう変えたいか（色、大きさ、雰囲気など）。「もっと明るく」「やわらかく」のようなあいまいな希望は、具体案を2〜3案出して選んでもらう
- 参考にしたいサイトや画像があるか（あれば貼ってもらう）

## 2. 変える前の画面を撮る

```
python tools/screenshot.py before
```

`/tmp/issue-images/screens/` に、パソコン（`-pc`）とスマートフォン（`-sp`）の画面の画像が保存される。Read で開いて今の見た目を確かめる。特定のページを撮るときは、`python tools/screenshot.py before news/ファイル名.html` のように指定する。

## 3. 提案（ファイルはまだ変えない）

コメントで次のことを示す。

- 変える場所と内容を、見た目の言葉で箇条書きにする（例:「ボタン：緑の角丸 → 青の四角」）
- 色は、色の名前とカラーコードを並べて書く（例: 落ち着いた青 `#2b5fa8`）
- 影響する範囲（「サイト全体のボタンが変わります」など）
- 大きな変更では、変更点を2〜3案に分けて選んでもらってもよい

## 4. 変える（OKが出てから）

### 書き方の決まり

- **色・書体・角の丸みなどは、ファイル先頭の `:root` の設定を使う**。色を変えるときは、まず `:root` の値を変える。同じ色を各所に直接書かない
- 新しい色や値が必要なら、`:root` に名前（`--color-〜` など）と説明のコメントを付けて追加する
- テンプレートで使っている `class` 名を変えない・消さない（使われていない `class` を新しく作っても効かない）
- **スマートフォン表示を必ず保つ**：ファイル末尾の `@media (max-width: 〜px)` の部分を消さない。横にはみ出すような固定の幅を付けない
- **次の部分は消さない**（担当者の作業に必要）
  - `.preview-bar`：確認用ページの黄色い帯
  - `.badge-draft`、`.badge-scheduled`：「下書き」「公開予定」の印
- **読みやすさ**：文字と背景の色の差を十分にとる（薄いグレーの背景に薄い文字、などは避ける）。本文の文字は 16px 未満にしない
- **書体**：端末に入っている書体を使う。Google Fonts を使うときだけ、ファイルの先頭に `@import url("https://fonts.googleapis.com/…");` を書いてよい。それ以外の外部ファイルは読み込まない
- コメント（`/* 〜 */`）は日本語で、何のための設定かが分かるように書く

### 画面の部品と、対応する class

| 画面の部品 | class |
| --- | --- |
| ページの上部（会社名とメニュー） | `.site-header`、`.site-logo`、`.site-nav` |
| トップの大きな見出しの部分 | `.hero`、`.hero-kicker`、`.hero-title`、`.hero-text`、`.hero-actions`、`.hero-image` |
| ボタン | `.button`、`.button-ghost` |
| 各ブロックと見出し | `.section`、`.section-alt`（背景色つき）、`.section-head`、`.section-title`、`.section-link` |
| 下層ページの上部 | `.page-head`、`.page-kicker`、`.page-title`、`.page-lead` |
| お知らせ一覧 | `.news-list`、`.news-item`、`.news-title`、`.category` |
| 求人のカード | `.job-cards`、`.job-card`、`.job-card-title`、`.job-card-summary`、`.job-card-meta`、`.tag`、`.more` |
| 記事・求人のページ | `.breadcrumb`、`.article-head`、`.article-meta`、`.article-title`、`.article-lead`、`.article-image`、`.block-title` |
| 記事の本文（見出し、箇条書き、表、画像） | `.prose` |
| 会社概要・募集要項の表 | `.info-table` |
| 応募・お問い合わせの枠 | `.contact-box`、`.contact-title` |
| 一覧に戻るリンク | `.back-link` |
| ページの下部 | `.site-footer`、`.footer-name`、`.footer-contact`、`.copyright` |

## 5. 変えた後の画面を確かめる（必ず行う）

```
python build.py --check
python tools/screenshot.py after
```

- `after-` で始まる画像を Read で開き、`before-` の画像と見比べる
- 確かめること: 頼まれたとおりに変わっているか／文字が読みにくくなっていないか／要素が重なったり、はみ出したりしていないか／スマートフォン（`-sp`）で崩れていないか
- 「横にはみ出しています」と表示されたら、スマートフォンで横スクロールが出る状態なので直す
- おかしなところがあれば直して、もう一度撮る（2回まで。それでも難しければ、変更を小さくする）

## 6. 保存と返事

CLAUDE.md の「保存のしかた」に従う。返事には次のことも書く。

- 変えた内容を見た目の言葉で箇条書き（変更前 → 変更後）
- 「確認用ページは、パソコンとスマートフォンの両方で見てください」
- 元に戻したいときは `@claude デザインを変更前に戻して` と頼めば戻せること

## 戻すとき

デザインを元に戻す依頼は、restore の手順書に従う。`assets/css/style.css` の履歴を調べて戻す（`git log -- assets/css/style.css`、`git restore --source=<戻す先> -- assets/css/style.css`）。
