# 文章の修正・画像の差し替え・取り下げ

CLAUDE.md の「依頼の種類と進め方」に沿って進める。

## 1. 直す場所を探す

担当者は、ページの見た目やURLで場所を伝えてくる。次の順で探す。

1. 担当者が書いた文言（直したい元の文章）で検索する
   - Grep で `content/`、`site.yml`、`templates/` を検索する（例: 「平日 9:00」を探す）
   - 「エコプロの記事」「年末年始のお知らせ」のように記事の呼び名で頼まれたら、`content/news/` の各ファイルの `title` から探す
2. URLやページ名で伝えられたら、CLAUDE.md の「URL」の対応表でファイルを特定する
3. ページ別の文言のありか

| ページ・場所 | 文言のありか |
| --- | --- |
| すべてのページの会社名、フッターの連絡先 | `site.yml`（name、contact） |
| トップの大きな見出し・紹介文・画像 | `site.yml`（tagline、about、hero_image） |
| トップの会社概要 | `site.yml`（company） |
| 採用情報ページの説明文 | `site.yml`（jobs_lead） |
| 求人ページの応募先 | `site.yml`（recruit_contact） |
| お知らせ・求人の本文、項目 | `content/news/`、`content/jobs/` |
| ボタンの文字、「お知らせ」などの見出し | `templates/` |

- 見つからない、または **同じ文言が複数の場所にある** ときは、場所の候補を見せて、どれを直すか（全部か）を確認する
- 依頼が「ページ全体の雰囲気を変えたい」「配置を変えたい」などデザインに関わるときは、対応せず管理者に相談するよう伝える

## 2. 文章を直す

- 直し方が具体的（「〇〇を△△に」）なら、すぐ保存してよい。返事に **変更前 → 変更後** を書く
- 「もっと分かりやすく」「やわらかく」など、言い回しを考える必要があるときは、修正案を示してOKをもらってから保存する
- `templates/` を直すときは、文言だけを変える。`{{ }}`・`{% %}`・タグ・`class` には触れない
- 求人の条件（給与、勤務時間など）を変えるときは、`.claude/skills/job/SKILL.md` の「表現のチェック」も確認する
- 日付に曜日を書くときは `python build.py --weekday 日付` で確かめる
- お知らせの公開日（`date`）を変えても、**ファイル名は変えない**（ページのURLが変わり、古いURLが見られなくなるため）
- お知らせの組み立てや書き方を変えるときは、`.claude/skills/news/SKILL.md` の「本文の組み立て方」に従う

## 3. 画像を追加・差し替える

1. `/tmp/issue-images/list.txt` で、使う画像を確認する。画像が複数あり、どれを使うかはっきりしないときは確認する
2. どこに使うかがはっきりしないとき（「この写真を載せて」だけ、など）は、候補（トップの画像、記事の先頭、本文の途中など）を示して確認する
3. 画像を整えて保存する。差し替えのときも、**元の画像は上書きせず、新しい名前で保存する**（古い画像は履歴として残し、ブラウザに古い画像が残る問題も防ぐ）

```
python tools/prepare_image.py /tmp/issue-images/image-1.jpg images/site/top-20261007.jpg
```

4. 画像を表示している場所を、新しいファイル名に書き換える
   - トップの画像: `site.yml` の `hero_image`（と `hero_image_alt`）
   - お知らせ・求人の先頭の画像: その記事の `image`（と `image_alt`）
   - 本文の途中の画像: 本文の `![説明](images/...)`
   - 古いファイル名がほかで使われていないか、Grep で確認する
5. 画像の説明文（`image_alt` など）は、画像の内容が分かる短い文にする（例: 「本社の外観」）
6. 返事には、どこの画像をどう変えたかと、整えた結果（サイズなど）を書く

イラストを描き直す・新しく描くときは、`.claude/skills/illustration/SKILL.md` に従う。

## 4. 取り下げる（削除）・募集を締め切る

- 記事や求人の取り下げは、ファイルを削除せず `status: 非公開` にする
  - 担当者が「削除して」「完全に消して」と書いていても同じ。返事で「あとで元に戻せるよう、ファイルは残したまま非公開にしました。ホームページからは見えなくなります」と伝える
  - 記事に使っていた画像も消さない（ほかの記事で使っていなければ、表示されなくなるだけ）
- 対象の記事・求人がはっきりしているとき（タイトルが1つに決まるとき）は、確認を待たずに非公開にして保存してよい。返事に **どの記事を非公開にしたか**（タイトルと公開日）を書く
- 非公開にすると、確認用ページでも一覧と記事のページから消える。公開ボタンを押すと、本番でも消える（記事のページのURLを開くと「見つかりません」になる）
- 返事の最後に「元に戻したいときは `@claude 〇〇の記事を元に戻して` と頼めば、公開の状態に戻せます」と添える
- 「〇日で締め切る」ときは、`status` は「公開」のまま、`end_date` にその日付を入れる（その日を過ぎると自動で表示されなくなる）
- 取り下げた記事を復活させるときは、`status` を「公開」に戻す
- 対象がはっきりしないときは、`content/news/` や `content/jobs/` の一覧（タイトル・日付・状態）を番号付きの表で見せて選んでもらう

## 5. 保存

CLAUDE.md の「保存のしかた」に従う。
