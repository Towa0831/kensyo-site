# 会社ホームページ（GitHubのIssueから更新する仕組み）

GitHubのIssueに `@claude` と書いて頼むだけで、お知らせ・求人の作成、文章の修正、画像の差し替えなどができるホームページです。更新作業はすべてGitHubの中で完結します。

```
① Issueに「@claude ○○したい」と書いて作成
      ↓ 自動
② Claudeがコメントで返事（質問・文章の提案・修正内容の報告）
      ↓ 「@claude これでOK」とコメント（小さな修正は①のあとすぐ保存されます）
③ Claudeが下書きを保存
      ↓ 自動
④ 確認用ページ（GitHub Pages）が更新され、URLがコメントで届く
      ↓ 見た目を確認して、Claudeの返事の「Create PR」から公開申請を作る
⑤ 公開申請で「Squash and merge」→「Confirm squash and merge」
      ↓ 自動
⑥ 本番サイトに反映（https://hisazumi-test.com/kensyo/）
```

- **予約公開**：公開日を未来にすると、その日の朝6時ごろに自動で公開されます
- **掲載終了**：掲載終了日を決めると、その日を過ぎたら自動で非表示になります
- **差し戻し**：すべての変更が履歴として残るので、いつでも前の状態に戻せます
- **画像の自動調整**：スマートフォンの大きな写真も、自動で縮小・向きの補正・撮影場所などの情報の削除をしてから使います

## 1. 最初の設定（1回だけ）

### 1-1. Claude GitHub App をリポジトリに入れる

1. https://github.com/apps/claude を開き、「Configure」（初めてなら「Install」）を押します
2. 自分のアカウントを選び、「Only select repositories」でこのリポジトリを選んで保存します

### 1-2. シークレットを登録する

**Settings → Secrets and variables → Actions** に、次の4つを登録します。

| 名前 | 中身 |
| --- | --- |
| `CLAUDE_CODE_OAUTH_TOKEN` | パソコンのターミナルで `claude setup-token` を実行して表示されたトークン（Claudeの Pro 以上のプランが必要） |
| `FTP_SERVER` | XserverのFTPホスト名（`sv○○○○.xserver.jp` の形。`ftp://` や末尾の `/` は付けない） |
| `FTP_USERNAME` | FTPのユーザー名 |
| `FTP_PASSWORD` | FTPのパスワード |

Claudeが動くたびに、`CLAUDE_CODE_OAUTH_TOKEN` の持ち主のClaudeの利用枠を使います。

### 1-3. 確認用ページ（GitHub Pages）を使えるようにする

1. **Settings → Pages** を開き、「Build and deployment」の **Source** を **「GitHub Actions」** に変えます
2. **Settings → Environments** を開き、**「github-pages」** を選びます（1の操作で自動で作られます。なければ、一度下書きを保存すると作られます）
3. 「Deployment branches and tags」を **「No restriction」** に変えて保存します
   （初期設定では main からしか公開できず、Claudeの下書きから確認用ページを作れないため）

注意：

- **非公開（Private）リポジトリでGitHub Pagesを使うには、GitHubの有料プラン（Pro など）が必要**です。無料プランの場合、Settings → Pages に「Upgrade」などの案内が表示されます。その場合は、リポジトリを公開（Public）にするか、有料プランにします
- 確認用ページのURLは、知っていれば誰でも見られます（検索エンジンには載らない設定にしています）。まだ公開前の内容が表示されることに注意してください

### 1-4. Actions の設定を確認する

**Settings → Actions → General** の「Actions permissions」が「Allow all actions and reusable workflows」（初期設定）になっていることを確認します。

### Claudeは何を読み込んで動くのか

GitHub上のClaudeは、作業のたびにこのリポジトリの次のファイルを読み込みます。Claudeの動き方を変えたいときは、ここを書き換えます。

| ファイル | 内容 |
| --- | --- |
| `CLAUDE.md` | 全体のルール（話し方、進め方、触ってよいファイル、守ること） |
| `.claude/skills/news/SKILL.md` | 新しいお知らせの作り方（記事の形の提案 → 必要な情報を聞く → 完成案 → 保存） |
| `.claude/skills/news/article-types.md` | お知らせ記事の型（展示会出展、休業案内など）ごとの、おすすめの見せ方と必要な情報。型を増やすときはここに追記 |
| `.claude/skills/illustration/SKILL.md` | 写真がないときのイラストの描き方 |
| `.claude/skills/design/SKILL.md` | デザイン（色・文字・余白など）の変え方 |
| `.claude/skills/job/SKILL.md` | 新しい求人の作り方（法律上必要な項目、表現のチェック） |
| `.claude/skills/edit/SKILL.md` | 文章の修正、画像の差し替え、取り下げのやり方 |
| `.claude/skills/restore/SKILL.md` | 前の状態に戻すやり方 |

## 2. 使い方

### 依頼する

1. リポジトリの **「Issues」タブ → 「New issue」** を押します
2. タイトルに短い説明、本文に `@claude` とやりたいことを書いて「Create」を押します。写真は本文にドラッグ＆ドロップすれば添付できます

   ```
   @claude 年末年始休業のお知らせを出したいです。
   12/29〜1/4がお休みで、1/5から通常営業です。
   12月1日に公開してください。
   ```

3. 1〜3分ほどで、Claudeがコメントで返事をします
4. 返事にはコメントで答えます。**コメントの先頭に `@claude` を付けてください**（付けないとClaudeは反応しません）

### 依頼の例

| やりたいこと | 書き方の例 |
| --- | --- |
| お知らせを出す | `@claude エコプロの出展を告知したい` |
| 記事の相談をする | `@claude 何かお知らせを出したいです。おすすめはありますか？` |
| チラシからお知らせを作る | `@claude この画像のイベントのお知らせを作って`（画像を貼る） |
| 求人を出す | `@claude パートの配送スタッフを募集したい。午前中だけ、週3日〜、時給1,100円` |
| 文章を直す | `@claude トップページの「地域の暮らしを、もっと心地よく。」を「地域とともに、50年。」に変えて` |
| 誤字を直す | `@claude 年末年始のお知らせの「順時」を「順次」に直して` |
| 連絡先を変える | `@claude 電話番号を 000-111-2222 に変えて` |
| 画像を差し替える | `@claude トップページの写真をこれに変えて`（画像を貼る） |
| 記事に写真を足す | `@claude 年末年始のお知らせの最初に、この写真を入れて`（画像を貼る） |
| イラストを直す | `@claude エコプロの記事のイラストの人を3人にして` |
| 求人の条件を変える | `@claude 一般事務の求人の給与を「月給23万円〜」に変えて` |
| 募集を締め切る | `@claude 配送スタッフの募集を今月末で締め切って` |
| 記事を取り下げる | `@claude 「ホームページを公開しました」のお知らせを消して` |
| 前の状態に戻す | `@claude 昨日公開したお知らせを、公開前の状態に戻したい` |
| 確認だけしたい | `@claude 今公開している求人の一覧を教えて` |

- **新しいお知らせ**は、Claudeがまず「おすすめの記事の形」と「記入用の一覧」を返します。一覧をコピーして分かるところを埋めて返事をすると、Claudeが文章・画像（写真がなければイラスト）・見せ方まで考えた完成案を出します。`@claude タイトルは案2で` のように直し、よければ `@claude これでOK` と答えると保存されます
- **新しい求人**は、Claudeがまず文章を提案します。直し方・OKの出し方はお知らせと同じです
- **「〇〇を△△に」のようにはっきりした小さな修正**は、Claudeがすぐ保存し、変更前 → 変更後を報告します
- **前の状態に戻す**ときは、Claudeが履歴を見せて確認してから戻します

### 確認して公開する

1. Claudeが保存すると、1〜2分後にIssueに **「確認用ページを更新しました」** というコメントが届きます。リンクを開いて見た目を確認します（上部に黄色い「確認用ページです」の帯が出ます）
2. 直したいところがあれば、同じIssueで `@claude ○○を直して` と頼みます。Claudeは前回の変更を引き継いで直します
3. 問題がなければ、**Claudeの最新の返事** の下にある **「Create PR」** のリンクを押し、開いた画面で **「Create pull request」** を押します。これが公開申請です
4. 公開申請のページで **「Squash and merge」→「Confirm squash and merge」** を押します。2〜3分後に本番サイトに反映されます
5. 元のIssueが開いたままなら、「Close issue」で閉じます

公開申請を作ったあとに直したいところが見つかったら、**公開申請のページ**のコメント欄に `@claude ○○を直して` と書きます。確認用ページのURLも、公開申請のページに届きます。

### 注意

- **1つのIssueでは、1つの用件**を扱います。別の用件は新しいIssueで依頼してください
- 「Create PR」のリンクは、**いちばん新しい返事のもの**を使ってください
- 確認用ページは1つだけです。別の下書きを保存すると、その内容に置き換わります
- ページの追加やメニューの並び替えなど、ページの構成の変更は、Claudeは対応しません（管理者が行います）。色や文字の大きさなどのデザインの変更は頼めます

### 困ったとき

| 困りごと | 対処 |
| --- | --- |
| Claudeが返事をしない | コメントに `@claude` が付いているか確認してください。Actionsタブで「Claude（Issueからの更新）」が失敗していないかも確認します |
| 確認用ページのURLが届かない | Actionsタブで「確認用ページを更新」の結果を確認します。失敗している場合は「1-3」の設定を見直してください |
| 確認用ページが変わらない | 反映まで1分ほどかかります。ページを再読み込みしてください |
| 画像が使われなかった | 画像をもう一度コメントに貼り、`@claude この画像を使って` と書いてください |
| 急いで本番から消したい | 「Pull requests」タブの「Closed」から、その内容を公開したときの公開申請を開き、一番下の「Revert」→ 新しくできた公開申請で「Squash and merge」→「Confirm squash and merge」を押すと、2〜3分で元に戻ります |

### ほかの人も使えるようにするとき

今は自分のアカウントだけで使えます。あとで担当者を増やす場合は、担当者にGitHubアカウントを作ってもらい、Settings → Collaborators から招待します（Write 権限）。Claudeは書き込み権限のある人の依頼にだけ反応します。

## 3. 仕組みの詳細

### ワークフロー

| ファイル | 動くとき | すること |
| --- | --- | --- |
| `claude.yml` | Issueやコメントに `@claude` が書かれたとき | Issueの画像をダウンロードし、Claudeが返事・作業をする |
| `preview.yml` | Claudeが下書きを保存したとき（`claude.yml` から呼び出される） | 確認用ページを生成して GitHub Pages に公開し、URLをコメントで知らせる |
| `deploy.yml` | main に反映されたとき、毎朝6時ごろ | 本番ページを生成してXserverにアップロード、公開の記録（タグ）を残す |

### ファイル構成

```
├── content/
│   ├── news/          お知らせ（1記事＝1ファイル）
│   └── jobs/          求人（1職種＝1ファイル）
├── images/            画像（news/、jobs/、site/）
├── site.yml           会社情報、トップページの文章・画像
├── templates/         ページのひな形（デザイン）
├── assets/css/        デザインの色や文字の設定
├── build.py           ページを生成するプログラム
├── tools/             画像を整える・イラストや画面を確かめるプログラム
├── CLAUDE.md          Claudeへの作業ルール
├── .claude/skills/    Claudeの作業手順
└── .github/
    ├── scripts/       Issueの画像をダウンロードするプログラム
    └── workflows/     自動処理の設定
```

### 記事の状態

| status | 本番サイト | 確認用ページ |
| --- | --- | --- |
| 公開（公開日が今日以前） | 表示 | 表示 |
| 公開（公開日が未来） | 公開日の朝6時ごろから表示 | 「公開予定」の印付きで表示 |
| 下書き | 表示しない | 「下書き」の印付きで表示 |
| 非公開 | 表示しない | 表示しない |

掲載終了日（`end_date`）を過ぎたものは、どちらにも表示しません。

### 本番ドメインが決まったら

`deploy.yml` の `server-dir` と、`CLAUDE.md` に書かれている本番サイトのURLを書き換えてください。

### 手元でページを生成する

```
pip install -r requirements.txt
python build.py            # 本番用（dist/ に生成）
python build.py --preview  # 確認用
python build.py --check    # データとひな形のチェックだけ
```

### バックアップと差し戻し

- 変更はすべてGitの履歴に残ります。本番に公開するたびに `release-日付-時刻` のタグも付きます
- `@claude ○○を前の状態に戻して` と頼めば、Claudeが履歴を調べて戻します
- 記事・画像は削除せず「非公開」にしたり新しい名前で保存したりする運用なので、取り下げた記事や前の画像にもすぐ戻せます
